# 给你看的项目说明

这个仓库是我准备拿来做简历项目的，方向是一个小红书电商运营工具。

你先不用把所有代码都看完，先知道它要做什么、怎么跑、哪些地方还需要真实测试就行。

## 这个项目是干什么的

完整流程是：

```text
录入商品
→ AI 生成 3 个不同风格的带货笔记
→ 选择一个版本并修改
→ 自动上传图片
→ 自动挂载店内商品
→ 立即发布或定时发布
```

目前只做这条主流程，没有加库存、订单、数据报表之类的功能。

## 现在已经写好的部分

- 商品库：名称、图片、商品 ID、卖点、标签
- AI 生成：种草、测评、促销三个版本
- 内容编辑：标题、正文和标签可以修改
- 多账号：每个账号单独保存登录状态
- 发布任务：立即发布、定时发布、重试、取消、删除
- 自动挂商品：优先用商品 ID，匹配不到再用商品名称
- 发布日志：失败原因会记录下来
- Windows 和 macOS/Linux 的安装、启动脚本

## 你先看这几个文件

### `app/ui/main_window.py`

主界面和四个页面都在这里：

- 首页生成
- 商品库
- 发布任务
- 设置

### `app/services/content_service.py`

AI 文案生成逻辑在这里。

没有配置 API Key 时会走本地示例，方便先看流程。

### `app/services/publisher.py`

自动发布和挂商品逻辑在这里，这是最需要真实账号测试的部分。

### `app/database.py`

商品、账号和发布任务都存在 SQLite 里，表结构和增删改查都在这里。

### `scripts/save_login_state.py`

用来打开浏览器登录小红书，然后保存登录状态。

## 怎么跑起来

### Windows

先双击：

```text
install.bat
```

安装完成后双击：

```text
start.bat
```

### macOS / Linux

```bash
chmod +x install.sh start.sh
./install.sh
./start.sh
```

## 第一次测试怎么做

建议按这个顺序：

1. 先启动程序，确认四个页面能正常打开。
2. 在商品库添加一个测试商品。
3. 不配置 API Key，先测试本地生成三个文案版本。
4. 运行 `scripts/save_login_state.py`，登录一个测试用的小红书账号。
5. 在设置里添加账号登录态。
6. 建一个发布任务。
7. 用测试商品和测试账号观察一次完整发布流程。

## 目前最需要你帮忙看的地方

主要是 `app/services/publisher.py`。

因为小红书后台页面可能变化，下面这些定位可能需要根据实际页面调整：

- 上传图文按钮
- 标题输入框
- 正文编辑框
- 添加商品按钮
- 商品搜索框
- 商品复选框
- 保存按钮
- 发布按钮

如果运行时提示“未找到某个控件”，基本就是对应的 Playwright 定位器需要改。

## 现在还没有真实验证的部分

代码语法和本地单元测试已经过了，但下面这些没有真实店铺账号就不能完全确认：

- 登录态能否长期复用
- 当前小红书发布页元素是否完全匹配
- 商品 ID 精确匹配是否稳定
- 挂商品后能否正常保存
- 发布后作品确认是否稳定
- 平台验证码、滑块和风控情况

所以暂时不要直接拿正式账号批量发布，先用测试账号跑一遍。

## 项目数据放在哪里

运行后本地数据在：

```text
~/.xhs_ecom_note_assistant/
```

里面有：

- 配置文件
- SQLite 数据库
- 日志文件

登录态和 API Key 不要提交到 GitHub。

## 项目当前目标

这个项目不是准备做成大型产品，主要目标是：

- 两周左右可以完成
- 能稳定演示
- 简历上能写
- 面试时能讲清楚完整业务流程

后续优先修发布稳定性和补界面截图，不继续加复杂功能。
